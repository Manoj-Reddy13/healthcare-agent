# Member 3 data services and Member 4 integration extension

This folder is a repository-ready addition. It runs beside the original backend and exposes both original and new routes on one server. Existing app, frontend, agent, requirements and documentation files need no changes to run this preview.

## Quick start

Place this folder at `healthcare-agent/backend/member3_extension`. From it, on Windows PowerShell:

```powershell
./setup.ps1
./verify.ps1
./run.ps1
```

Requires Python 3.10+, internet access for the first dependency installation, and the original backend at the parent `backend` folder. Stop another server on port 8000 before starting. Open `http://127.0.0.1:8000/docs`.

Manual/other-platform equivalent after activating your own Python virtual environment:

```text
python -m pip install -r requirements-integration-v4.txt
python rebuild.py
python doctor.py
python -m unittest discover -v
python -m uvicorn evidence_api_v5:app_factory --factory --host 127.0.0.1 --port 8000
```

Set HEALTHCARE_ORIGINAL_BACKEND only if the original backend is elsewhere. Set MEMBER3_DATABASE only to select a different prepared snapshot. The server is local-only. No secrets are needed for our standalone services.

## What is implemented

- Hospital city/specialty lookup with source-linked evidence and review dates.
- Price-batch validation and import to a separate snapshot; exact INR handling.
- Exact treatment/package cost range selection with date, room, billing-unit and provenance checks.
- Treatment-specific budget filtering, including combined specialty/budget filters when both datasets exist.
- Conditional scheme rule evaluation with AND/OR groups, missing-information results and no stored personal answers.
- Provider-specific published price observations and dated official PM-JAY senior-path screening.
- Relational SQLite pilot schema, source/evidence records, repeatable data import and directory rebuild.
- Independent APIs, original-route composition, contract compatibility audit and tests.

The original `/api/*` routes still use the original implementation. New sourced services use `/api/v2/data/*`; published evidence uses `/api/v3/evidence/*`. Shared hosting is complete. Existing UI/agent source-aware wiring is not.

## Data and generated files

`data/` contains source JSON and collection templates. `schema.sql` defines the pilot database. `rebuild.py` creates `.local/` snapshots from those inputs, checks for source changes, and refuses to silently replace a different snapshot. Use `python rebuild.py --output NEW_FOLDER` to build a separately reviewed snapshot.

Generated `.local/`, temporary `.scratch/`, Python caches and `.venv/` stay out of Git through this folder's own .gitignore. No database binaries or installed dependencies are required in the source archive. Tests create synthetic prices only inside temporary test databases.

The datasets currently contain two sourced hospitals, eight specialty relationships, one exact treatment variant, three CGHS reference tariffs and three published clinic-price observations. Draft treatment families are labelled separately. Full accepted self-pay cost records and complete current scheme/participation data are not present. Cost endpoints return unavailable where needed.
